# TonyPi `go_to_tag` 离散视觉闭环状态机

## 目标与坐标约定

- 目标：依次导航到指定的 10 cm、`36h11` AprilTag；每个目标最终满足相机光心到
  Tag 中心距离 `0.50 ± 0.08 m`、正前方云台下 `|bearing| ≤ 5°`、
  `facing_error ≤ 10°`，停稳后连续三帧确认才报告到达。
- 每次只执行**一个有限动作组**，等待动作完整结束并停稳，再取新画面决策；不使用
  `times=0` 连续动作，不用预先标定的动作位移或速度决定走几步。
- 除原地转体搜索外，机身平移必须以当前可见的目标 Tag 为依据；每次机身动作前
  先将云台置于 `PWM1=1500/PWM2=1435`，等待稳定并重新观测。所有距离和 bearing
  均基于云台正前方的观测。
- `theta=90°` 定义为相机光轴左右各 `45°` 的**控制范围**，
  `alpha=60°` 定义为机身正前方左右各 `30°` 的**接近范围**。两者是预设阈值，
  不宣称已测得相机的稳定检出视场；Tag 是否可见仍以实际检测结果为准。

## 状态机的两个硬件接口

状态机只依赖两个操作；动作组名称是动作接口的唯一显式参数，读画面接口无参数：

```python
def execute_action(action_group: str) -> None: ...
def observe_tags() -> FrameObservation: ...
```

- `execute_action(name)` 仅接受当前导航允许的动作组名称。内部完成云台正前方复位、
  有限动作组执行（`times=1`）、必要的安全停止以及等待动作和机身停稳；成功返回
  只表示 SDK 调用已结束，**不保证机身产生预期位移**；可检测到的失败抛出执行错误。
  deadline/取消等运行上下文由接口对象在创建时获取，而不是给状态机增加 SDK
  控制调用。
- `observe_tags()` 内部确保云台在 `1500/1435` 正前方且稳定，然后读取**一帧新
  画面**并返回该帧检出的所有 Tag ID 与位姿，以及采集时间。目标 ID 由状态机
  从结果中选择，不作为接口参数；未检出目标用该帧结果中的“无目标”表达，
  相机读帧失败则抛出错误。三帧到达确认必须调用三次，不能复用缓存帧。
- 状态机中不直接使用除此以外的 TonyPi SDK API，包括云台 PWM、
  `runActionGroup()`、`stopActionGroup()` 或相机设备接口；这些都封装在上述两个
  操作的实现及其初始化/清理生命周期中。状态机只处理目标选择、状态转换、
  选择动作组、deadline/取消与结果。
- 单步调用顺序为 `observe_tags()` → 决策 → `execute_action(name)` →
  `observe_tags()`；搜索时同样如此，只允许在目标不可见时选择原地转体动作。
  动作接口还需保证多个动作组不会并发执行。SDK 可能吞掉内部异常，因此状态机
  不根据动作接口返回值推断位移，只根据动作后的新画面重新决策。

## 单步循环

每次机身动作结束后，等待停稳，再取得新鲜 Tag 位姿并重新判断状态。有限动作
不中途以视觉帧切换为下一动作。取消或 deadline 在动作前后检查；SDK 的动作组
正在执行时，仍需要在可停止范围内响应取消/期限，并在完全停下后才重新决策。

云台不左右扫描。搜索动作是一次有限的小步原地转体；转体前后云台均复位正前方。
目标不可见时不前进、后退或横移，只能继续有界搜索，直到检出、取消或 deadline。

## 状态和转换

### SEARCH_ALIGN（搜索、机身对准）

- 初始 Tag 不可见或其他状态丢失 Tag：进入本状态。每次只执行一个有限的小步原地
  转体，回正云台并重新观测。搜索使用任务剩余时间作为边界，不以动作次数无进展
  报错。若检测到 Tag，则根据正前方 bearing 的符号逐步转体，使 Tag 靠近画面中央。
- 正前方观测到目标且 `|bearing| ≤ 30°`：进入 `APPROACH`；若此时距离已在目标
  范围内，直接进入 `TERMINAL_ALIGN`。
- 检出的 Tag 若处于 `30° < |bearing| ≤ 45°`，仍按方向逐步转体；超出 `45°`
  的观测不能作为允许前进的依据。Tag 再次丢失则继续搜索。

### APPROACH（接近）

- Tag 不可见：立即回 `SEARCH_ALIGN`；在重新检出前不执行平移。
- `|bearing| > 30°`：回 `SEARCH_ALIGN`，通过转体重新对准；不可在本状态
  盲目前进。
- Tag 可见、在 `alpha` 内、距离大于 `0.58 m`：执行一次有限的
  `go_forward_one_step`，停稳后重新观测。
- 距离进入 `[0.42, 0.58] m`：进入 `TERMINAL_ALIGN`。接近阶段不以
  `facing_error` 决定横移。
- 距离小于 `0.42 m`：转入终端距离修正，避免继续前进。

### TERMINAL_ALIGN（终端校正）

- Tag 不可见：回 `SEARCH_ALIGN`；`|bearing| > 30°`：回搜索对准。
- 距离大于 `0.58 m`：回 `APPROACH`；距离小于 `0.42 m`：选择一个有限的
  后退小动作，结束后重观测距离，不允许继续向前。
- `|bearing| > 5°`：先选择一次有限小步转体，使 Tag 向画面中央移动，再重新
  检查距离、bearing 与 facing。
- bearing 已居中但 `facing_error > 10°`：根据 Tag 法线与视线的**有符号**
  水平偏差，选择一次有限的左移或右移。横移结束后重新观测；如果 bearing
  不再居中，优先转体将 Tag 重新居中，然后重新检查距离和 facing。不能以
  `facing_error` 的无符号值单独决定横移方向。若有符号偏差不足以确定方向，
  保持静止并继续观测或等待总 deadline，不猜测横移方向。
- 所有终端条件满足时，停稳并取得连续三帧新鲜观测；其中任一帧不满足则回本状态
  继续决策。

## 终止和异常

- 整条路线沿用上层指定的 deadline；没有指定时使用 `120 s`。搜索、动作、
  等待停稳和三帧确认都计入该期限。无进展或状态往返**不另设失败次数/超时**；
  只由总 deadline 终止这类情况。
- 取消、相机读取失败、动作组缺失或执行故障等实际错误立即停止并报告；这不属于
  “无进展失败”。不可把检测不到目标当作允许继续平移。
- 当前连续运动实现以及“初始 Tag 不可见立即失败”的策略在落地时必须被直接
  替换，不能保留并行的旧控制路径。

## 实现前需验证的硬件边界

- `go_forward_one_step`、转体、横移及有限后退动作是否都能在 SDK 下按
  `times=1` 完整执行和可靠停止；特别是旧 `back` 的 SDK 起步/结束行为不同于
  普通动作组，不能直接当作一小步后退。
- 云台回正和动作组执行期间 SDK/相机是否保持独占；动作期间取消与 deadline
  如何中止并等待当前动作安全完成。
- 预设 `±45°` 不是检测稳定性的保证。如果实际相机视场或 Tag 投影不允许检出，
  以“不可见→只搜索、不平移”处理，而不伪造可靠观测。
