# TonyPi `go_to_tag` 离散视觉闭环状态机

## 目标与观测约定

`target_tags` 按给定顺序执行，每个目标均从正前方观测开始。目标是边长 10 cm 的
`36h11` AprilTag；相机光心至 Tag 中心距离须在 `[0.42, 0.58] m`，正前方观测的
`|bearing| ≤ 5°`、`facing_error ≤ 15°`，连续三帧满足才报告到达。正前方定义为
`PWM1=1500/PWM2=1500`。转头时的 Tag 位姿不能用于接近、终端校正或到达确认。

每次机身动作只执行一个有限动作组（`times=1`），等动作返回并停稳后重新观测；
禁止 `times=0`。相机持续采集并只保留最新帧；主机读帧时间和序号不能证明硬件
曝光时刻。正前方观测要在云台回正后开始新一次读取，不能复用已参与决策的帧。
动作组正常返回也不证明机器人完成预期位移，下一步仍依据实际观测决策。

`±45°` 是正前方的预设控制范围，`±30°` 是允许接近的范围，均不是已测得的相机
稳定检出视场。寻找不可见目标时允许云台扫描和**原地**有限转体；平移必须有正前方
当前可见目标的依据。不可见目标的机身搜索使用 `turn_left` / `turn_right`，每次
只运行一次动作组并重新观测；按用户实测约 14 次转到背后，搜索最多走 16 次再
转头复查。一个目标的不可见转体累计最多 32 次，作为安全上限，不代表精确一圈，
也不沿用此前 `*_small_step` 每圈约 32 次的标定。

## 硬件 seam 与云台扫描

状态机只调用以下硬件操作，不直接访问 PWM、相机或 TonyPi SDK：

```python
def observe_tags() -> FrameObservation: ...
def scan_head(tag_id: int, on_sample: Callable[[HeadScanSample], None]) -> HeadScanResult: ...
def execute_action(action_group: str) -> None: ...
```

`observe_tags()` 回正云台并等待稳定，只返回正前方新帧的全部 Tag 位姿和读帧时间。
`execute_action()` 在云台正前方执行一个允许的动作组，处理取消、deadline 和安全
停止。`scan_head(...)` 保持机身静止，在用户确认安全的水平舵机 2 范围内，
从中位 `1500` 向右逐段扫到 `500`；仍未确认目标时一次回正到 `1500`，
再向左逐段扫到 `2500`。中途回正不逐段扫描，也不把回正期间的画面用于方向
判断。扫描期间相机持续采集并只保留最新帧，但运动期间的画面不参与 Tag 检测。
每段移动 100 PWM，等待命令规定的转动时间和稳定时间后，再从此刻开始读取新帧
检测；检出目标仅作为候选，再取另一张新帧确认。未检出或确认失败时继续扫描
剩余位置；确认成功才返回
相对机身的左/右方向；扫描结束仍未确认则返回“未发现”。函数返回前必须回正云台，
回正后再次检查取消和 deadline，不能将回正期间发生的中断报告为目标未找到。
官方 `ColorTrack.py` 中目标在画面右边时减小舵机 2 脉宽，因此以小于 `1500` 为
右侧、大于 `1500` 为左侧；若现场舵机方向与此不符，必须停止搜索而非反向盲转。

扫描帧都必须在每段停稳后开始读取，主机读帧时间仍不能证明真实曝光时刻；
不得按运动中的伺服命令位置推算精确机身 bearing。停头确认帧只用于选择转体
方向；只有机身转动后回正云台并再次 `observe_tags()`
看到目标，才能进入正常导航。扫描期间也要检查取消和整条路线的 deadline；相机
失效或云台控制失败是错误，不允许返回“未发现”掩盖故障。扫描所见目标、停头确认
结果及正前方决策帧须能在回放和日志中按目标 ID 与时间顺序对应；每帧通过
`on_sample` 即时记录，即使扫描中途故障，已取得的帧也不能丢失。

## 状态及转换

`OBSERVE_TARGET` 是**每个目标**的入口，也是每步动作后的分发点。优先检查取消、
deadline 和硬件错误；成功到达目标后才切换到下一个 ID。不可见转体计数只在切换
目标时清零，目标短暂可见后再次丢失不重置预算。

| 状态 | 转换条件 |
|---|---|
| `OBSERVE_TARGET` 正前方观测 | 目标不可见 → `HEAD_SCAN`；可见且 bearing 绝对值大于 30° → `ALIGN_VISIBLE_TARGET`；可见、在接近范围内且距离大于 0.58 m → `APPROACH`；其余 → `FINAL_ALIGN`。本状态不执行机身动作。 |
| `HEAD_SCAN` 转头寻找 | 执行一次有界云台扫描；任一小段停稳后新帧检出目标候选 → `VERIFY_HEAD_DETECTION`；未发现 → `BODY_SCAN`。初始目标和路线中后续目标使用同一规则。 |
| `VERIFY_HEAD_DETECTION` 停头核验 | 云台在当前小段终点停稳，用新帧确认；确认目标 → `TURN_TOWARD_DETECTION`；未确认 → 回到进入此状态前的 `HEAD_SCAN` 或 `REAR_HEAD_SCAN`，继续剩余扫描。本状态在一次 `scan_head(...)` 调用内部完成，不执行机身动作。 |
| `TURN_TOWARD_DETECTION` 朝发现方向转身 | 云台回正，沿确认的方向每次执行一次 `turn_left` 或 `turn_right` 并重观测；正前方看到目标 → `OBSERVE_TARGET`；未看到且不可见转体尚未满 32 次 → 保持同向继续；第 32 次后仍未看到 → `FAILED(TARGET_NOT_FOUND)`。 |
| `BODY_SCAN` 原地搜索 | 扫头没有确认目标时选定一个方向，每次执行一次 `turn_left` 或 `turn_right` 并用正前方新帧检查；看到目标 → `OBSERVE_TARGET`；16 次后仍未看到 → `REAR_HEAD_SCAN`。计入同一目标的 32 次总预算，不足 16 次时受剩余预算限制。 |
| `REAR_HEAD_SCAN` 背后转头寻找 | 执行一次有界云台扫描；小段停稳后的新帧检出候选 → `VERIFY_HEAD_DETECTION`；扫完仍未确认 → `FAILED(TARGET_NOT_FOUND)`；确认目标后继续使用剩余转体预算。 |
| `ALIGN_VISIBLE_TARGET` 对准可见目标 | 仅在正前方看见目标时，根据 bearing 符号执行一个标准有限转体，然后回 `OBSERVE_TARGET`；不可见时不沿用旧 bearing，转 `OBSERVE_TARGET`。 |
| `APPROACH` 接近 | 目标在正前方可见、bearing 绝对值不大于 30°且距离大于 0.58 m → 用下一侧脚的镜像动作组前进一步；然后回 `OBSERVE_TARGET`。其他条件直接回该分发状态。 |
| `FINAL_ALIGN` 终端校正 | 目标不可见或超出接近范围 → `OBSERVE_TARGET`；距离大于 0.58 m → `APPROACH`；距离小于 0.42 m → 后退一步；bearing 绝对值大于 5° → 使用较小的 `_a` 转体动作；否则 facing error 大于 15°且法线水平角与 bearing 的差值绝对值大于 2° → 沿有符号方向横移一步。每个动作后回 `OBSERVE_TARGET`；横移方向不确定时保持静止并重观测；全部合格 → `ARRIVAL_CONFIRM`。 |
| `ARRIVAL_CONFIRM` 连续确认 | 每次调用正前方观测取得新帧，三个终端条件连续满足三次 → `ADVANCE_TARGET`；任一帧不满足 → 计数清零，回 `OBSERVE_TARGET`。 |
| `ADVANCE_TARGET` 路线推进 | 发布当前目标到达进度；还有目标 → 更新目标 ID、清零不可见转体预算，进入 `OBSERVE_TARGET`；否则 → `COMPLETE`。 |
| `COMPLETE` / `FAILED` | 终态，不再执行动作。 |

`BODY_SCAN` 每次连续搜索的方向只选择一次，途中不重新随机；正前方重新看到目标后
结束该次连续搜索，若以后再次丢失，重新从头部扫描开始，但累计的 32 次预算不清零。
`TURN_TOWARD_DETECTION` 的方向
来自停头确认而非随机。两者每一步都重新观测，一旦看到当前目标立刻停止盲转。
若目标在正常导航途中丢失，也返回 `OBSERVE_TARGET` 并先扫头；该目标已经消耗的
不可见转体预算仍有效，不能因重进搜索而再次获得 32 次动作。普通 `turn_left` /
`turn_right` 仅用于不可见目标的原地搜索；可见目标的粗对准仍使用 `*_small_step`，
终端居中继续使用更小的 `*_small_step_a`。接近阶段不按预先
标定的动作位移决定前进次数。

前进只使用 `go_forward_one_step_left` 和 `go_forward_one_step_right`，不再使用
原始 `go_forward_one_step`。每个任务从左脚动作开始，两种动作组按完成次数交替；
切换 Tag、转向、后退或横移均不重置轮换，也不消耗下一侧脚的顺序。只有当前
前进动作组成功返回才切换下一次使用的动作组；动作中断或失败时立即终止任务。
SDK 正常返回仍不代表真实位移已得到确认，之后必须按新观测决定是否继续前进。

## 终止、回放与硬件边界

整条路线沿用上层 deadline，未指定时默认 120 秒；云台扫描、等待稳定、转体、
接近和到达确认都计入期限。第 32 次不可见转体之后仍应取一帧新观测；目标仍不可见
才报 `TARGET_NOT_FOUND`。`REAR_HEAD_SCAN` 无结果也报同一错误。取消、相机故障、
动作组文件缺失或执行故障立即终止；SDK 内部可能打印并吞掉动作异常，成功返回
不可解释为真实位移确认。普通状态往返不另设“无进展次数”错误。

回放保留每次参与正前方决策的原图、全部 Tag 位姿、目标、阶段、决策、动作与计时；
扫描发现候选和停头确认应记录扫描方向、云台目标脉宽、检测帧、确认结果，以及
确认成功时选定的机身转身方向。回放必须明确标记非正前方观测，不能把其距离和
bearing 误作正常导航数据。当前图像时间戳
仅是主机读帧时间，不是硬件曝光时间。
回放页须直接内嵌每帧的关键观测与动作摘要，打开本地 `index.html` 时不依赖
`fetch()` 读取 JSON；同名 JSON 仍保存全部记录，动作结束及下一帧确认的动作效果
也应同步更新页面内的摘要。

现场必须核对 PWM2 增减方向、扫描位置不会拉扯线缆、停头确认帧是否足够清晰；
当前 TonyPi SDK 的转体动作组不支持可靠的中途物理停止，因此机身仍按有限小步
闭环，而不是扫描视频发现目标就中断动作组。
